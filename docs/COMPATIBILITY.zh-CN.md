# 与 json-server 的兼容对照

[English](COMPATIBILITY.md)

对照版本：v1 = `1.0.0-beta.15`（npm dist-tag latest），v0.17 = `0.17.4`。下面的说法来自把同一批请求发给真实服务器的结果，用 [`scripts/compare-all.sh`](../scripts/compare-all.sh) 复现。

| 写法 | 默认模式 | `--legacy` |
|---|---|---|
| 集合/单例 CRUD、`GET /db`、写操作即时保存 | 支持；`DELETE` 返回被删对象（v1） | 支持；`DELETE` 返回 "{}"（0.17 实测） |
| `field:op=value`（`eq/ne/lt/lte/gt/gte/in/contains/startsWith/endsWith`，点号嵌套字段） | 按 v1 运算符解析（`eq` 严格相等、`contains` 系不区分大小写，按 `matches-where` 源码） | 整名当未知字段忽略（0.17 实测：`views:gt=3` 返回全量） |
| `field_后缀=value`（`_gt/_gte/_lt/_lte/_ne/_in/_contains/...`） | 按 v1 后缀表识别 | 按 0.17 后缀表识别 |
| `field_like=value` | 正则匹配、不区分大小写（每请求编译一次） | 同左（0.17 原生） |
| 未知字段 `field=value` | 字段在所有记录里都不存在时忽略这个参数（与 0.17 一致，防缓存参数 `?_=1699` 不会让列表变空，见 D19）；字段存在但值不匹配仍返回空；显式 `field:op=value` 不适用，字段不存在就是不匹配 | 忽略（0.17 原生） |
| `q=value` | 全文匹配：任意字段（含嵌套）的字符串形式包含该值，不区分大小写，数字和布尔也算命中（与 0.17 一致）；`q=` 空值视为没有传。v1 beta.15 实测 `q` 恒 0 命中，JsonSrv 不复刻（D5） | 同左（0.17 原生） |
| 同名参数重复 `a=1&a=2` | 等值重复=或（与 0.17 一致，v1 实测最后一个生效，见 D15）；`_ne` 重复全部生效（且）；`:op` 重复按 v1 最后一个生效 | 全部值参与：非 `_ne` 或、`_ne` 且（0.17） |
| `_sort`（`-` 前缀、逗号多字段） | v1 语义：空值挤末尾、缺失与 null 保序、字符串忽略大小写 | lodash 式排序：null 排在末尾、大小写敏感（0.17 实测） |
| `_order=desc,asc`（全局或逐字段） | 按位置应用到 `_sort`（`-` 前缀优先） | 同左（0.17 原生） |
| `_start`/`_end`/`_limit` 切片 | 切片（`_end` 排他）并回显 `X-Total-Count` + `Access-Control-Expose-Headers`；仅 `_start` 时不切片不发头（与 0.17 一致） | 同左（0.17 原生） |
| `_page`/`_per_page` 包裹对象 | "{data,first,prev,next,last,pages}"（页号，实测）；非法值自动修正（`_page=abc` 按第 1 页、`_per_page=0` 按 10 条） | `_page` 按 10 条/页切片并输出 `Link`+`X-Total-Count`（0.17 实测），`_per_page` 忽略 |
| `_page` + `_limit` | 仍是包裹对象，`_limit` 当每页条数 | 数组 + `Link`/`X-Total-Count`（0.17） |
| `_embed=单数/复数` | v1 式嵌入：复数=子资源嵌入、单数=父资源嵌入 | 0.17 式展开，但**不等于** `_expand`：无匹配目标时得 `post: []`（空数组挂到每条记录，0.17 实测），复数目标才做外键挂载 |
| `_expand=复数` | 0.17 式展开：名字复数化找目标集合、按 `<单数>Id` 外键挂到每条记录；单条与列表都支持、同名重复全部生效。**语义不等于 `_embed`** | 同左（0.17 原生） |
| `_dependent=<子集合>` | 删除父记录时，一并删除该子集合里外键指向它的记录（重复或逗号分隔可指定多个）；不传不级联 | 同左；另外不管传不传，都会清理外键指向已消失记录的孤儿记录（0.17 实测） |
| `_where=JSON` | 完整 v1 条件树："{字段:{运算符:值}}"、顶层 "{"or":[...]}" / "{"and":[...]}"（满足任一 / 全部满足；`and` 与 `or` 同构）；非法 JSON 回退普通条件 | 未知参数忽略（0.17 实测） |
| 嵌套路由 `/posts/1/comments` | 始终识别。GET 按路径原文比较外键（数字和字符串外键都能匹配，`007` 不会匹配数字 7）；父不存在返回 200 空数组。POST 外键：请求体给了就保留；否则父存在时取其 id 原值（数字还是数字，`12e4` 还是字符串），父不存在时取路径原文 | 始终识别；父不存在返回 200 空数组；POST 外键一律写路径原文字符串，覆盖请求体（0.17 实测） |
| `--routes` 重写文件 | 支持（0.17 格式，暂不支持动词前缀如 `GET /api/*`） | 同左 |
| POST 空请求体 | 201，按 `{}` 创建（与两版原版一致） | 同左 |
| POST 生成 id | 11 位随机短串 | id 全为数字时自增最大值+1；纯字符串 id 集合生成随机短串 |
| 表单/`text/plain` 请求体 | 任意 `Content-Type` 按 JSON 解析（v1） | 表单按 urlencoded 解析、`text/plain` 忽略请求体（0.17） |
| JSONP `callback` | 按未知参数处理：没有 `callback` 字段时忽略（与 0.17 一致，见 D19） | 参数删除（0.17 保留参数）；两模式都不实现 JSONP 包装 |
| 大整数字面量（超出 JS 安全整数） | 保留原文输出（原版按 JS 双精度改写，见 D12） | 同左 |
| 响应体格式 | 紧凑单行 JSON；数据文件写回保持 2 空格缩进与键顺序 | 同左 |
| `--` 选项终止符 | `jsonsrv -m a.js --port 3000 -- db.json`：`--` 之后全部按位置参数 | 同左 |
| `-m/--middlewares` JS 中间件 | 不支持：脚本扩展名（`.js/.cjs/.mjs/.ts`）参数明确提示，其余参数仍按位置处理 | 同左 |
| 首页 HTML、静态文件、CORS、gzip、`--delay`、`--read-only`、配置文件、`--quiet` | 支持 | 支持 |

## 已知差异（对照实测登记）


对照测试（[`scripts/compare.py`](../scripts/compare.py)）把与原版的差异登记在 `KNOWN` 表中：规则级登记（`@rule:<字段>`，写死具体值、跨请求复用）与请求级登记（含结果集按 id 序列一条），每条带准确理由与本表编号。比较器校验编号双向存在；登记之外按语义豁免的形态差异列在第二条清单里：

**与登记表一一对应的有意差异（编号 D1–D20，与 `KNOWN` 登记 reason 双向对应）**：

- **D1 v1 beta.15 的 id 字符串化与严格匹配（实测怪癖）**：原版读库时把数字 id 转成字符串，嵌入与外键匹配用严格相等，导致数字数据下 `?id:in=` 查不到、`id:ne` 近乎无效果、`?_embed=` 外键匹配不到。JsonSrv 保留数字 id 原类型、按数值等价匹配：保留原类型才能让 `:in`、外键、`_embed` 在数字数据上正常工作，写库也不改变用户文件的数值形态。`:in`/`:ne` 运算符在普通字段上与实现一致、对照无差异；差异只在 id 字段受字符串化影响。
- **D2 `GET /db` 全量读取**：v1 beta.15 实测不支持 `GET /db`（404）；JsonSrv 按 README 支持（与 0.17 一致）。原版怪癖，登记为有意差异。
- **D3 嵌套路由**：v1 不支持嵌套路由（`/categories/1/books` 实测 404），JsonSrv 按 0.17 支持（含父记录不存在时的 GET 返回 200 空数组、POST 自动补外键；默认模式亦如此）。
- **D4 POST 显式重复 id**：v1 beta.15 实测不查重、直接 201 追加新记录；JsonSrv 返回 409 冲突拒绝写入（重复写入多半是调用方错误，追加会产生两条同 id 记录）。连带的数据文件与写后读回计数差异一并登记。
- **D5 `q` 全文检索**：v1 beta.15 实测 `q` 命中 0 条（README 声称支持全文检索但实际不生效）；JsonSrv 按 0.17 深度匹配（数字、布尔转字符串也算命中，不区分大小写）。对照计划按实际结果集差异登记。
- **D6 CORS 回显 Origin**：JsonSrv 带 `Origin` 时回显该 Origin 并发 `Access-Control-Allow-Credentials: true`（v1 beta.15 实测固定 `*`、不发凭据头；0.17 实测同为回显 Origin+凭据，故 017 计划无此差异），便于前端带 Cookie 联调。
- **D7 `Vary` 头**：JsonSrv 输出 `Vary: Origin, Accept-Encoding`（v1 beta.15 实测不发 `Vary`；与 0.17 对齐；`--legacy` 的 POST 另按 0.17 实测追加 `X-HTTP-Method-Override` 令牌）。
- **D8 首页 HTML**：`GET /` 两侧都是精简 HTML，页面内容允许不同（语义等价，登记 `@HTML`）；0.17 的 `charset=UTF-8` 大写与 Go net/http 固定小写 `utf-8` 亦语义等价。
- **D9 JSON 响应 Content-Type**：v1 beta.15 不带 `charset`；JsonSrv 始终带 `charset=utf-8`（按 0.17 惯例），语义等价；0.17 的 `charset=UTF-8` 大写与 Go 的小写 `utf-8` 语义等价。
- **D10 默认模式识别 0.17 写法**：`_limit`、`_start`/`_end` 切片（附 `X-Total-Count`）、`_order`、`_like`、`_expand`、同名参数重复、`_where` 的 `"and"`、`_page`+`_limit`——v1 beta.15 不识别这些写法、按字段过滤返回空数组，JsonSrv 默认模式按 0.17 识别。排序比较语义仍按 v1（空值挤末尾、字符串忽略大小写），与 0.17 lodash 码位序的差异一并登记。
- **D11 `_page`/`_per_page` 非法值修正**：v1 包裹对象下 `_page=abc` 按第 1 页、`_per_page=0` 按 10（非法值自动修正）；v1 beta.15 实测行为不同，登记为有意差异。
- **D12 大整数字面量精度**：v0.17 与 v1 beta 都把 JSON 数字解析为 JS `Number`（IEEE-754 双精度），超出安全整数的字面量会被改写（`12345678901234567890` → `12345678901234567000`）；JsonSrv 全程保留原文，无损输出。登记见 extrav1/extra017 计划 `GET /nums/1` 与写组 `file.nums[0].big`。

- **D13 冒号操作符语法**：默认模式支持 `field:op=value`（`:eq`/`:in`/`:ne` 及 v1 运算符，v1 语法）；0.17 实测把未知冒号参数整体删除（返回全量），两侧按设计不同。`--legacy` 保持 0.17。
- **D14 数组包含（有意放宽）**：普通 `field=value` 用于数组字段时任一元素相等即命中（0.17 把数组转字符串 `"a,b"` 后比较；v1 beta 同样不支持数组语义）；有意放宽，`--legacy` 保持 0.17。
- **D15 同名参数重复 = OR 全部值**：普通等值重复 `field=a&field=b` 按全部值取 OR，非数组字段与 0.17 实测一致；对照里的差异只出现在数组字段，来自 D14 的包含语义（`tags=b&tags=c`：0.17 得 `[2,4]`，默认模式还命中 `tags:["a","b"]`）。v1 beta 实测最后一个值生效。
- **D16 未知 `_embed` 目标**：默认模式对不存在的集合不加键（与 v1 beta 实测一致）；0.17 给每条记录挂 `x: []`，`--legacy` 保持 0.17。
- **D17 null 参数匹配**：`field=null` 在默认模式命中 null 值字段（与 v1 beta 实测一致）；0.17 把它当字符串比较，实测 0 命中；`--legacy` 保持 0.17。
- **D18 排序字符串大小写**：默认模式按 v1 sortOn 语义（小写化比较、空值挤末尾并保持原位）；0.17 按 lodash 原生比较（大小写敏感、null 参与排序）。`_sort=name&_order=desc` 类顺序差异登记于此。
- **D19 未知字段的等值参数**：字段在所有记录里都不存在时，默认模式忽略这个参数（与 0.17 一致）；v1 beta.15 实测返回空数组。静默返回空会让带防缓存参数（`?_=1699`、`?t=1699`）的前端请求拿不到数据，所以不跟 v1。
- **D20 默认模式 POST 与 0.17 的差异**：默认模式 POST 按 v1 生成 11 位随机串 id、不发 `Location`；0.17 自增数字 id 并发 `Location`。v1 没有嵌套 POST，所以对照 0.17 时登记（外键字段本身两侧一致）；`--legacy` 与 0.17 无差异。

**比较器按语义豁免的形态差异（不算 FAIL，但如实列出）**：


- **错误响应体**：JsonSrv 用 `{"message": "<说明>"}`；v1 为 `{"error": "Not Found"}` 形态。状态码一致时（≥400）错误体按比较器规则豁免。
- **纯数字外键字符串**：比较器把 id 和外键字段里的纯数字字符串归一成数字，所以 `"007"` 和 7 在对照里不算差异；这类写入和匹配靠 `internal/httpapi/param_edge_cases_test.go` 的单元测试把关。
- **响应 JSON 格式**：JsonSrv 响应体为紧凑单行 JSON（原版为 2 空格缩进多行）；对照按解析后的 JSON 语义比较，结果完全等价。
- **生成的 id**：v1 模式为随机短串，JsonSrv 与原版 nanoid 均为 11 位字母数字短串；对照把 id 字段值归一化后比较。
- **`Infinity`/`NaN` 数据值**：JSON 无对应表示，JsonSrv 加载为 `null` 并在启动时警告一次（原版 JSON5 解析保留原值，写回时同样降为 `null`）。
- **`.json5` 写回**：写回为标准 JSON 并丢注释/宽松写法（v1 beta.15 实测同样丢，加载时提示一次）。
- **`--routes` 注入查询段的值转义**：JsonSrv 转义 `&`/`=`/`#`（0.17 原版此处不转义，存在注入 bug，这里不复刻）。
- **`--middlewares` 参数消费**：JsonSrv 只消费脚本扩展名（`.js/.cjs/.mjs/.ts`）参数，0.17 的 yargs 会把后随的所有非选项参数（含数据文件）一并吞进数组（另有 "--" 终止符按 yargs 语义支持）。

## 已知限制

- **嵌套字段和多字段排序的分页没有达标**（10 万条，阈值 100ms）：`_sort=author.name,-views&_page=2&_per_page=100` 中位数约 124–125ms，一直超标；`_sort=author.name&_page=2&_per_page=100` 约 100–101ms，卡在阈值上，有时超。原因：v1 sortOn 要把每条记录的参与字段规范化后再比较。其余查询全部达标，这两条都在 `scripts/perf-run.sh` 里，所以它目前退出码非零。
- **写入吞吐**：10 万条库 + 后台连续 POST 场景下 POST 平均约 260ms（含序列化与原子落盘）；读侧 GET p50、p90 都在 1ms 左右。极端大库（>20 万条）写入会更慢，属全文件重写设计的成本。
- **未验证的平台与场景**：单元测试在 CI 的 Linux、Windows、macOS 上都通过，和真实 json-server 的对照只在 Linux 上跑；首页 HTML、CORS、gzip 行为只在 curl 层面与原版对照，未在真实浏览器中验证；`--watch` 的文件监听在编辑器批量保存（原子写）下未做压力验证。
- **JS 中间件**：`-m/--middlewares` 需要 Node 运行时，JsonSrv 是单二进制，不支持执行 JS 脚本（明确提示而非静默忽略）。
- **默认模式的宽松匹配（沿用 v1 语义，未改）**：URL 值像数字时也会按数值比较，所以 `zip=02134` 能命中数字 `2134`，`n=05`、`n=1e3` 能命中 5、1000（0.17 不命中）；叶子字段为 `null` 时 `w_gte=0` 也会命中（JS 里 `null >= 0` 为真）。需要严格比较时用 `_where`。
